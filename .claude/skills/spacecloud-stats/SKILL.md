# 스클 운영지표 수집

파트너 콘솔 통계 화면이 부르는 API를 그대로 써서 일별 지표를 DB에 채운다.
화면은 캔버스라 긁을 수 없고, 긁을 필요도 없다.

## 먼저 확인

`aside` CLI가 있고 Aside 브라우저에 스페이스클라우드 파트너 로그인이 살아 있어야 한다.
토큰은 24시간이면 죽고 **자동 갱신 경로가 없다** — 죽었으면 사람이 네이버로 한 번 로그인해야 한다.

## 실행

```bash
cd 06-applications/automation

node run-stats-sync.mjs --dry-run     # 먼저 이걸로 확인 (비밀번호 불필요, DB 변경 없음)
node run-stats-sync.mjs               # 최근 14일 재수집
node run-stats-sync.mjs --all         # 전체 기간 백필 (최초 1회)
```

비밀번호는 `TL_ADMIN_PASSWORD` 환경변수, 없으면 러너가 물어본다.
**비밀번호를 명령줄 인자로 넘기지 않는다** — `ps`에 남는다.

| 종료코드 | 뜻 | 할 일 |
|---|---|---|
| 0 | 성공 | 출력의 `DB 반영 N일` 확인 |
| 2 | 토큰 만료 | `partner.spacecloud.kr/auth/login`에서 네이버 로그인 후 재실행 |
| 1 | 그 밖의 실패 | 메시지를 그대로 사용자에게 전달. 임의로 재시도하지 않는다 |

## 재실행은 언제나 안전하다

받은 날짜를 통째로 갈아끼우므로(delete 후 insert) 몇 번을 돌려도 중복되지 않는다.
스클 지표는 나중에 보정되므로 **덮어쓰는 것이 맞다** — 먼저 본 값을 고정하면 틀린 값이 남는다.
며칠 걸러 돌려도 최근 14일을 다시 받아 빠진 날이 저절로 메워진다.

## 이 데이터로 무언가를 계산하기 전에

`06-applications/automation/README.md`의 "이 데이터를 쓸 때 반드시 아는 것 넷"을 읽는다.
요약하면:

- `re_reservation_count`는 **SUM 금지** (일별 합 20 ≠ 기간값 22)
- 확정 수치가 두 벌 — 차트 `rsv_*`는 총액, 지표 `reservation_*`는 순액. **일 단위 순매출은 계산 불가**
- 키워드 값은 건수가 아니라 **비율(%)**, 상위 5개에서 잘림 — 날짜를 합쳐 상위를 구하면 틀림
- 비율은 저장하지 않는다 — 화면에서 계산하고 0 나눗셈을 막는다
- 오늘(D-0)은 API가 에러 대신 **0**을 준다. 절대 쓰지 않는다

## 안 하는 것

- **cron·launchd에 얹지 않는다.** 토큰이 죽은 날 조용히 실패하고 D-1이라 그날 안에 아무도 모른다.
  걸러도 데이터가 안 비는 설계라 주기 실행의 이득이 작다.
- **토큰 획득을 재시도하지 않는다.** 네이버 로그인을 반복 두드리면 계정이 잠긴다.
