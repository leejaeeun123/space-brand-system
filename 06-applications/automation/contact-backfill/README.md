# 연락처 백필 자동화 — 가능성 검증 중

Gmail 경로로 들어온 예약은 연락처·이메일이 비어 있다(알림 메일에 아예 안 실려온다).
파트너 API에는 있으므로 **자동으로 메울 수 있는가**를 확인하는 단계다.

**아직 자동화는 없다.** 여기 있는 건 "무인으로 될까?"를 재는 자다.

## 결론 (2026-08-04 기준)

**현재 근거로는 무인화가 안 된다.** 파트너 토큰은 브라우저 localStorage에만 있고 24시간이면 죽는데,
갱신하려면 네이버 OAuth를 태워야 하고 **네이버 세션이 없으면 로그인 폼에서 멈춘다** — 사람만 뚫는다.

| 관측 | 방법 | 의미 |
|---|---|---|
| 인증 쿠키 **0개** (GA·채널톡·Datadog뿐) | `document.cookie` — HttpOnly는 이 방법으로 안 보인다. 엄밀히 하려면 devtools로 확인한다 | 토큰이 유일한 자격증명 |
| 토큰 삭제 → 앱이 `{}` 쓰고 로그인 페이지로 | localStorage 제거 후 재방문 | 자동 갱신 경로 없음 |
| 네이버 OAuth → `nidlogin.login`에서 6초+ 정지 | 네이버 버튼 클릭 후 URL 추적 | **세션 없으면 무인 불가** |

`automation/README.md`의 "네이버 세션은 몇 달에 한 번 끊긴다"는 서술이 **틀렸다.**
8/3 로그인 다음 날인 8/4에 이미 세션이 없었다. 실측이 아니라 추정이었다.

## 열린 질문 — 이게 다음 결정을 정한다

**"로그인 상태 유지"를 켜고 네이버에 로그인하면, 세션이 며칠을 버티는가?**

- **버틴다** → 무인 백필 가능. LaunchAgent + 시간당 멱등 스윕으로 간다
- **금방 끊긴다** → 반자동이 상한. 토큰 갱신만 사람이 하고 나머지는 자동

이 답이 나오기 전에 자동화 본체를 짜는 건 두 번째 추측이다. 그래서 여기서 멈췄다.

## ⚠️ 로그인 직후 제일 먼저 — 재검증보다 앞선다

**빈 연락처부터 메운다.** 2026-08-04 시점에 `민인기` 건의 연락처가 비어 있었고, 다른 건도 있을 수 있다.
그 예약이 취소되면 스클이 연락처를 마스킹해 **어느 경로로도 영구히 못 가져온다.**

```js
// partner.spacecloud.kr/reservation 콘솔에 spacecloud-api-sync.js 붙여넣은 뒤
await scSync.fillContacts('<admin.html 비밀번호>', { dryRun: true })
await scSync.fillContacts('<admin.html 비밀번호>')
```

세션 수명 재검증은 며칠 기다려야 하지만 이건 기다릴 이유가 없다. 순서를 바꾸지 않는다.

> 2026-08-04 세션에서 무인 획득을 검증하다 그 시점의 유효 토큰을 지웠고 복구하지 못했다.
> 그래서 이 백필이 **로그인 전까지 막힌 상태로 남았다.** 로그인은
> `partner.spacecloud.kr/auth/login`을 새로 열어서 한다 — 그때 열려 있던 `nid.naver.com` 탭은
> `oauth_token`·`state`가 박혀 있어 시간이 지나면 만료되므로 그걸 재사용하지 않는다.

## 재검증 절차

```bash
cd 06-applications/automation/contact-backfill
npm install          # 최초 1회

npm run setup        # 크롬이 뜬다. 네이버로 로그인 — "로그인 상태 유지"를 반드시 켠다
# ... 며칠 지난 뒤 ...
npm run spike        # 사람 없이 토큰이 나오는지 검증
```

`npm run spike`가 핵심이다. **토큰을 일부러 지우고 시작한다** — 안 그러면 "이미 토큰 있음"으로
통과해 아무것도 검증하지 못한다. 네이버 쿠키는 남겨두므로 24시간 뒤 실제 상황과 같다.

출력이 `무인 획득 성공`이면 무인화로, `무인 획득 실패`면
`~/.typelounge/spike/verify-failed.png`에 막힌 화면이 찍히니 무엇이 끼었는지(로그인 폼 /
동의 화면 / 기기 인증 / 캡차) 보고 판단한다.

> 8/4에 이 확인을 브라우저 확장(claude-in-chrome)으로 하려다 `nid.naver.com`에서 막혔는데,
> 그건 **확장의 사이트 권한** 문제이지 사이트 방어가 아니다. Playwright에는 그 제약이 없어
> 네이버 도메인에서도 URL 추적과 스크린샷이 된다 — 위 약속은 실제로 성립한다.

## 구성

| 파일 | 역할 |
|---|---|
| `session.js` | 전용 크롬 프로필로 토큰 확보. 자동화 본체가 어느 쪽으로 결론나든 그대로 쓴다 |
| `spike-token.js` | 위 검증 러너. `--setup`으로 세션을 심고, 기본 모드로 무인 복구를 시험한다 |

**전용 프로필을 쓰는 이유** — 일상 크롬과 섞으면 자동화가 로그인 상태를 건드릴 때 사람 브라우저가
같이 흔들린다. 기본 경로는 `~/.typelounge/spacecloud-profile`(`SC_PROFILE_DIR`로 변경 가능)이고
**iCloud 동기 폴더 밖**이다 — 프로필 자체가 자격증명이다.

## 설계에서 되돌리면 안 되는 것

- **토큰 획득 실패를 재시도하지 않는다.** 네이버 로그인을 반복 두드리면 계정이 잠긴다.
  CLAUDE.md의 "ThinQ PAT 401을 재시도하지 않는다"와 같은 이유다.
- **`headless`를 기본값으로 두지 않는다.** 네이버·Cloudflare가 헤드리스를 탐지하면 로그인이 막히고,
  그 실패는 "토큰 못 받음"으로만 보여서 원인 추적이 어렵다. 시스템 크롬(`channel: 'chrome'`)을
  쓰는 이유도 같다.
- **스크린샷을 레포에 저장하지 않는다.** 화면에 예약자 정보가 찍힌다. `~/.typelounge/spike/`로 뺀다.

## 자동화 본체를 짤 때 (아직 아님)

결론이 어느 쪽이든 이 구조는 그대로다:

- **DB를 먼저 본다.** `admin_list_reservations`로 빈 칸만 추려 그 `booking_no`로만 상세를 부른다.
  `p_booking_no`가 곧 API의 `d.id`라 목록 엔드포인트는 아예 안 불러도 된다. 정상 상태면 0건이라
  비공식 API를 대부분 건드리지 않는다. (지금 `spacecloud-api-sync.js`의 `fillContacts`는
  매번 전 페이지를 긁는다 — 수동 실행이라 괜찮았지만 주기 실행에는 부적합하다.)
- **`control-agent` 프로세스에 넣지 않는다.** 조명이 거기 걸려 있다. Playwright가 행되면
  조명 제어까지 조용히 같이 죽는다. 별도 LaunchAgent job으로 띄운다.
- **주기는 시간당 1회.** 데드라인이 "언젠가"가 아니라 **"취소되기 전"**이다 — `RCCMP`가 되는 순간
  스클이 연락처를 마스킹해 영구 소실된다. 맥은 잠드니 고정 시각 약속이 아니라 **깨어날 때마다
  빈 칸을 전부 따라잡는 멱등 스윕**으로 짠다.
- **실패를 `console.warn`으로 흘리지 않는다.** 무인 실행에서 아무도 안 본다.
  Mattermost 웹훅이 이미 있으니 같은 채널(`e-alert-typelounge`)로 보낸다.
  특히 **토큰 만료는 반드시 알린다** — 조용히 멈추면 연락처가 계속 비는 걸 아무도 모른다.
- **`booking_no`가 null인 행은 이 경로로 영원히 안 채워진다.** `admin_fill_contact`가
  `booking_no`로만 매칭하기 때문이다(미매칭 시 exception). 별도 알림 카테고리로 빼서 사람이 손본다.

## 막혔을 때

| 증상 | 확인 |
|---|---|
| `npm run spike`가 로그인 폼에서 멈춘다 | 네이버 세션이 끊긴 것. `npm run setup`을 다시 돌린다 |
| 크롬이 안 뜬다 | `/Applications/Google Chrome.app` 존재 여부. `channel: 'chrome'`은 시스템 크롬을 쓴다 |
| `profile in use` | 같은 프로필로 다른 크롬이 떠 있다. `pkill -f spacecloud-profile` |
| 토큰은 있는데 API가 401 | 24시간이 지났다. 재로그인 말고는 길이 없다 |
