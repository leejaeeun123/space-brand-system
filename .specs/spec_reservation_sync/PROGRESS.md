## 결정 기록

### 수집 경로를 둘 둔다 (2026-08-03)
- **결정:** 파트너 API를 주 경로로, Gmail 메일 파싱을 백업으로 둘 다 유지한다.
- **대안:** (a) API 단독 — 데이터는 완전하지만 토큰이 24시간이면 죽고 브라우저가 필요해 무인 불가.
  (b) Gmail 단독 — 무인으로 돌지만 연락처·이메일·사용목적이 영영 비고, 비공식 API 사양 변경 시 무방비.
- **사유:** 둘의 구멍이 정확히 반대다. 취소건 실명은 메일에만, 연락처는 API에만 있다.
  중복 비용은 예약번호 대조 한 번이라 거의 공짜다.

### 취소를 삭제가 아닌 상태 변경으로 (2026-08-03)
- **결정:** `cancelled boolean` 플래그를 두고 `admin_set_cancelled`로 바꾼다. 행은 지우지 않는다.
- **대안:** 취소 메일을 받으면 해당 행을 `delete`한다.
- **사유:** 지우면 이용 이력이 비고, 같은 행에 달린 문자 장부·자동화 실행 표시가 함께 사라진다.
  또 재예약 겹침을 분별하려면 취소된 행이 남아 있어야 한다 — 지우는 설계는 이 판별을 원천봉쇄한다.

### 취소 대상을 이름으로 특정하고, 애매하면 사람을 부른다 (2026-08-03)
- **결정:** (날짜+시작+종료) 후보를 예약자명으로 좁히고, 같은 이름의 취소 행과 활성 행이
  공존하면 자동 처리 대신 Mattermost로 사람을 부른다.
- **대안:** 후보 중 `!cancelled` 첫 행을 그냥 취소한다(초기 구현).
- **사유:** A가 취소한 슬롯을 B가 재예약하면 한 슬롯에 두 행이 공존한다. 이때 A의 취소 메일이
  재처리되면 무고한 B가 취소된다. 반대로 모호한 경우를 그냥 스킵하면, 손님은 취소된 줄 아는데
  예약이 살아 있어 그 시각에 냉난방·조명이 돌아간다. 둘 다 피하려면 사람을 부르는 수밖에 없다.

### `end_hour`를 +1 보정한다 (2026-08-03)
- **결정:** 파트너 API의 `end_hour`를 포함값으로 보고 `p_end = end_hour + 1`로 저장한다.
- **대안:** 일반적인 API 관례대로 exclusive로 가정하고 그대로 넣는다.
- **사유:** 예약 9건 전수 대조에서 호스트 페이지 표기("16~19시, 3시간")와 일치했고, 단가로도
  교차 검증됐다 — `13-20 / 64,000원`은 inclusive 8시간 × 8,000원으로 떨어지지만 exclusive 7시간이면
  9,142.86원이라는 단가가 나온다. 안 보정하면 모든 예약이 1시간씩 짧게 들어간다.

### 예약번호 unique 인덱스를 partial로 (2026-08-03)
- **결정:** `where booking_no is not null` 조건부 unique 인덱스.
- **대안:** 컬럼 전체에 unique 제약.
- **사유:** 전화 예약 같은 수동 입력은 예약번호가 없어 null이다. 전체 unique면 둘째 수동 예약부터
  들어가지 못한다. **대가로** null은 중복이 막히지 않아, Gmail 파서가 예약번호를 못 찾을 때
  조용히 null로 넣지 않고 에러로 승격시킨다(후속 결정).

### 메일을 스레드가 아닌 메시지 단위로 처리 (2026-08-04, #16)
- **결정:** 처리한 `messageId`를 스크립트 속성에 기록해 거른다. 라벨은 사람이 보는 표시로만 남긴다.
- **대안:** 스레드에 라벨을 붙이고 `-label:`로 제외하는 기존 방식.
- **사유:** 스클은 모든 예약 메일 제목이 같아 Gmail이 한 스레드로 묶는다. 라벨이 붙은 뒤 들어온 메일은
  쿼리에서 통째로 사라져 **예약이 조용히 누락**됐다. 2026-08-03 예약 스레드는 5건이 한 덩어리였고,
  15분 트리거가 그걸 한 번에 담는 것은 구조적으로 불가능하다.

### 연락처 백필은 반자동이 상한이다 (2026-08-04, #17)
- **결정:** 무인 백필을 지금 만들지 않는다. 사람이 토큰만 갱신하고 나머지를 스크립트가 하는 반자동으로 둔다.
- **대안:** LaunchAgent + 시간당 멱등 스윕으로 완전 무인화.
- **사유:** 토큰은 24시간이면 죽고 리프레시 토큰도 인증 쿠키도 없다. 네이버 OAuth로 갱신하려 했더니
  세션이 없으면 `nidlogin.login`에서 멈췄다(8/3 로그인 다음 날인 8/4에 이미 세션이 없었다).
  세션 수명을 재측정하기 전에 무인 본체를 짜는 것은 두 번째 추측이라 거기서 멈췄다.
