## 결정 기록

### 시도 제한은 실패한 인증만 센다 (2026-08-13)
- **결정:** 성공한 인증도, 자격증명을 아예 안 보낸 요청도 카운터에 올리지 않는다.
- **대안:** 모든 요청을 IP별로 세는 일반 레이트 리밋.
- **사유:** pg_cron이 1분마다 anon으로 `automate`를 부른다. 그걸 세면 자동화가 스스로 문을 잠그고
  무인 공간이 조용히 죽는다 — #44·#70에서 자동화 침묵이 실제로 두 번 일어난 뒤라 이 구분을 넣었다.

### 장부를 못 읽으면 통과시킨다(fail-open) (2026-08-13)
- **결정:** `auth_attempts` 조회가 실패하면 제한을 건너뛰고 통과시킨다(로그는 반드시 남긴다).
- **대안:** fail-closed — 조회 실패 시 전부 차단.
- **사유:** 무인 공간에서 fail-closed는 DB 장애를 곧 '어드민 현장 대응 불가 + 자동화 정지'로 바꿔버린다.
  그 기대 피해가 대입 공격보다 크고, 공격자가 이 조회를 일부러 실패시킬 수단도 없다.

### 틀린 자격증명을 guest로 낮추지 않는다 (2026-08-07 계약, 2026-08-13 재확인)
- **결정:** `password`를 보냈는데 admin과 안 맞으면 401이다. guest 권한으로 강등시키지 않는다.
- **대안:** 틀린 비밀번호를 무시하고 guest로 처리 — 손님 경로가 어차피 비밀번호 없이 동작하므로 가능했다.
- **사유:** 강등시키면 `admin.html`의 오타가 "비밀번호가 맞지 않아요"가 아니라 알 수 없는 403으로 보인다.
  같은 이유로 청소 토큰은 `password`에 겸용하지 않고 별도 필드로 받는다.

### 시도 제한 키는 `cf-connecting-ip` (2026-08-13)
- **결정:** `cf-connecting-ip`를 키로 쓴다. `x-forwarded-for`는 Cloudflare를 안 거치는 환경용 폴백이고,
  그때만 마지막 항목을 쓴다.
- **대안:** XFF 첫 항목 / XFF 마지막 항목 — 둘 다 처음에 시도했다.
- **사유:** 플랫폼이 클라이언트 XFF를 그대로 통과시켜 목록 전체가 호출자 손에 있다(위조 13회 미차단 실측).
  `cf-connecting-ip`는 클라이언트가 보내면 Cloudflare가 요청을 403으로 거부해 위조값이 도달하지 못한다.
- **⚠️ 전제:** 앞단이 Cloudflare여야 성립한다. 앞단 구성이 바뀌면 이 결정을 다시 해야 한다.

### 전환 마이그레이션이 순서를 강제한다 (2026-08-13)
- **결정:** 비밀번호가 안 심긴 상태에서 전환·회수 마이그레이션을 밀면 예외를 던져 **전체 롤백**시킨다.
- **대안:** 문서에 순서를 적고 사람이 지키기 — 처음에는 그렇게 했다.
- **사유:** `supabase db push`에 '여기까지만' 옵션이 없어 미적용분을 전부 민다. 순서를 틀리면
  어드민이 통째로 잠기고, 무인 공간에서 그건 현장 대응 불가다. 잠긴 채 남는 것보다 아예 안 바뀌는 쪽이 낫다.

### 두 뿌리를 같은 값으로 맞춰야 한다 (2026-08-13)
- **결정:** Edge Function 시크릿 `ADMIN_PASSWORD`와 SQL `admin_secret`을 **같은 비밀번호**로 유지한다.
- **대안:** 어드민 화면이 Edge Function 하나만 거치게 만들어 뿌리를 하나로 합치기.
- **사유:** 합치려면 어드민 화면의 모든 RPC 호출을 Edge Function 경유로 바꿔야 하는데, 그건 반환 형태가
  `setof reservations`인 함수들을 건드리는 일이라 화면 전체가 위험해진다. 지금은 두 곳을 같은 값으로
  맞추는 운영 규율로 대신하고, 어긋나면 "화면은 열리는데 기기 제어만 안 됨"으로 드러난다.
