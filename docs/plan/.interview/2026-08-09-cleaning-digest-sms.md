## 선탐색 결과 (요약)

- `supabase/functions/control/sms/` — SOLAPI LMS 발송(`solapi.ts`) · 선점→발송→기록→알림 순서(`dispatch.ts`) · 시각 판정 순수함수(`schedule.ts`) · 문구 정본(`templates.ts`) · Mattermost 미러(`notify.ts`)
- `supabase/functions/control/handlers/automation.ts` — pg_cron 1분 틱 `automate`. 기기 자동화 + `sweepSms`가 각각 try/catch로 격리돼 얹혀 있다
- `supabase/functions/control/automation/store.ts` — `fetchRecent`가 어제~내일(KST) · `cancelled=false` 예약을 한 번에 가져오고, 기기·문자 판정이 **같은 배열**을 공유한다
- `supabase/functions/control/automation/windows.ts` — `endTime()`이 자정 넘김 예약(18:00~00:00)을 처리한다. 직접 `targetTime(date, end_time)`을 쓰면 종료가 시작보다 이르게 나온다(수정 #41)
- `supabase/migrations/20260808100000_sms_notify.sql` — `reservation_sms`. `reservation_id` NOT NULL FK + `kind` CHECK 5종 + 부분 유니크 인덱스로 중복 선점
- `06-applications/admin.html:899` — **청소 완료 체크 버튼이 이미 있다**(`cleaning_done` / `admin_set_cleaning`). 라이브 DB에만 있고 마이그레이션 밖이다
- `reservations`에 `guests`(인원)·`purpose`(용도) 컬럼 존재. **`purpose`는 Gmail 경로가 항상 null로 넣는다**(`spacecloud-gmail-sync.gs:193` — 메일 본문에 없음). 사람이 파트너 API 동기화를 돌린 예약에만 값이 있다
- 라이브 DB에 테스트 예약을 만들면 기기 자동화가 같이 돈다 — 2026-08-08 손님 이용 중 냉난방·조명이 덮인 사고(`control-setup.md` J절)

## 확정 항목

> **설계 단계에서 두 항목이 뒤집혔다. 현재 정본은 `.specs/spec_cleaning_sms/spec.md`다.**
> (1) "심야 변경을 다음 아침에 접어서" → **22:00 이후 억제**로 바뀌었다. 다이제스트가 날짜별로
> 나가므로 07:00 이전 변경은 애초에 '변경'이 아니었다. (2) "유예 60분" → **22:00까지**로 늘렸다.
> 60분이면 재발송 절차가 죽고 함수가 한 시간 죽은 날은 하루가 통째로 침묵했다.
> 사유는 `PROGRESS.md`의 결정 기록에 있다.

- **의도·배경**: 무인 운영이라 청소 담당자가 "오늘 언제 들어가면 되는지"를 알 방법이 없다. 예약은 스클에서 수시로 들어오고 취소·연장도 생기는데, 그걸 담당자에게 전달하는 경로가 지금은 사람뿐이다.
- **성공 지표**: 정량 지표 없음(정성 목표). 담당자가 문자 하나만 보고 그날 언제 갈지 정할 수 있으면 성공.
- **대상·역할**: **청소 담당자(내부 인력) 1명** — 문자 수신. 형운은 같은 내용을 Mattermost로 본다(문자 아님).
- **범위 — 할 것**: 아침 다이제스트(07:00) · 변경 안내(낮 즉시 / 심야는 다음 아침 합산) · Mattermost 동시 게시
- **범위 — 안 할 것**: 청소 완료 회신·확인 경로 · 어드민 수신자 관리 UI · 다이제스트 수동 재발송 버튼 · 손님에게 나가는 문구 변경
- **범위 — 나중**: 청소 완료 표시를 담당자가 직접 하는 경로(어드민 `cleaning_done`과 연동)
- **핵심 시나리오**:
  1. 07:00 담당자 폰에 문자 1통 — 당일 예약 목록(시각·이름·인원·용도)과 청소 가능 구간
  2. 같은 내용이 Mattermost에 동시에 올라간다
  3. 낮 12시에 15:00 예약이 새로 들어옴 → 담당자에게 변경 1통
  4. 23시에 내일 예약이 취소됨 → 지금은 안 보내고 내일 07:00 다이제스트에 반영
  5. 그날 예약이 0건 → "오늘 예약 없어요" 문자를 **그래도** 보낸다
- **엣지·네거티브**:
  - 예약이 30분 미만 간격으로 붙음 → 청소 창이 아니라 "연달림, 청소 시간 없음" 경고로 적는다
  - 자정에 끝나는 예약(18:00~00:00) → 청소 창은 그다음 날 얘기가 된다. `endTime()`을 반드시 통과한다
  - `purpose`가 비어 있음(Gmail 경로 예약) → 그 줄만 빼고 나머지를 적는다. 빈칸을 지어내지 않는다
  - 수신자 시크릿 미설정 → 조용히 건너뛰고 콘솔에만. 예약의 문제가 아니라 서버의 문제라 장부에 실패로 쌓지 않는다(`sweepSms`와 같은 판단)
  - 07:00 발송을 놓침(함수 다운) → 유예 60분까지 늦게라도 보내고, 넘기면 `expired`로 남기고 Mattermost에 ⚠️
- **제약**:
  - 채널은 문자(SOLAPI LMS 45원/통). 하루 1~4통 예상
  - 발송 시각 07:00 KST · 즉시 변경 안내는 07:00~22:00 사이에만
  - 청소 가능 최소 공백 **30분**
  - 담당자 번호는 **시크릿으로만** 주입한다(`CLEANING_SMS_TO`). 남의 개인 연락처라 코드·문서·커밋에 남기지 않는다
  - 라이브 DB에 테스트 예약을 만들지 않는다 — 같은 행이 기기 자동화의 입력이다
  - `main` 직접 푸시 금지. 브랜치 → PR → 스쿼시 머지
